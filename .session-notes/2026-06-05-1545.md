## What was done

### Picked up from session 4 mid-flight
Session 4 left the WASM build broken: `cargo build --target wasm32-unknown-unknown -p bevy_scene@0.1.0` failed with getrandom 0.3.4 refusing to compile for wasm32 without its `wasm_js` feature. Session 4 had (incorrectly) attempted `--cfg=wasm_js` as a RUSTFLAGS value and created `.cargo/config.toml` with that flag. That approach was wrong — getrandom 0.3.4 and 0.4.2 both check `#[cfg(feature = "wasm_js")]` (a Cargo feature), not a rustc cfg flag.

### WASM build fix
Added target-specific direct deps to `bevy_scene/Cargo.toml`:
```toml
[target.'cfg(target_arch = "wasm32")'.dependencies]
getrandom = { version = "0.3", features = ["wasm_js"] }
getrandom4 = { package = "getrandom", version = "0.4", features = ["wasm_js"] }
uuid = { version = "1", features = ["js"] }
```
Cargo feature unification propagates `wasm_js` to all transitive users (ahash→bevy_utils for 0.3, uuid for 0.4). WASM build passes.
